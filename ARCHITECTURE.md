# Q-Knee — Architecture

This document is the single authoritative description of what actually runs
in this repository today.

## The one-line answer

**The Next.js frontend + FastAPI backend is the primary, judged,
production interface.** A Streamlit dashboard (`qknee/ui/`, wrapped by a
repo-root `streamlit_app.py`) previously existed as the project's original
interface but has been removed — the project's active development (recent
commit history) is on the Next.js workstation, and the FastAPI backend is
no longer "quarantined" or exploratory: it's what `frontend/` actually
calls in production.

---

## The request path, end to end

Every request runs the same five pipeline stages
(`qknee/models/pipeline.py`'s `PipelineRunner` — see `README.md`'s "System
architecture" section for the full stage table):

```
frontend/  (Next.js/React, deployed separately -- Vercel)
   │  fetch(`${NEXT_PUBLIC_API_URL}/predict`, ...)   -- frontend/lib/api.ts
   ▼
extras/api/server.py  (FastAPI, "uvicorn extras.api.server:app")
   │  QKneeBackend.predict() -- extras/api/server.py
   ▼
qknee.models.pipeline.PipelineRunner
   │
   ▼
DataIngestion -> ResNet18FeatureExtractor -> QuantumDimReducer (PCA) ->
VQCClassifier (PennyLane) -> qknee.xai.gradcam
```

`extras/tests/test_deployment_config.py` proves `extras.api.server` imports
cleanly and serves `/predict`.

**No ML logic lives in `frontend/`.** `frontend/lib/api.ts` is a typed HTTP
client only: it builds `FormData`, calls `fetch`, and parses the JSON
response into the TypeScript types in `frontend/lib/types.ts`. There is no
ResNet/PCA/VQC/Grad-CAM code anywhere under `frontend/`, and none should
ever be added there — a Next.js app doing tensor math would duplicate, not
share, `qknee/models/`.

## Trustworthiness signals: one shared source, not two independent ones

Every prediction the API returns carries provenance and model-health
signals computed by two shared modules — never invented ad hoc per
endpoint:

- `qknee/observability/provenance.py` — one `classify()` function producing
  the `LIVE` / `PRECOMPUTED DEMO` / `MOCK/FALLBACK` / `CACHED` / `PROXY`
  vocabulary every `PredictionResponse`'s `provenance`/`provenance_label`/
  `model_source`/`quantum_execution` fields use.
- `qknee/observability/model_health.py` — one `inspect_vqc_checkpoint()` /
  `full_status()` / `quick_status()` set of functions, surfaced in
  `GET /health`'s `model_status` field, so "is there a real trained
  checkpoint" is answered identically everywhere it's asked.

The API never silently presents a randomly-initialized model's output as a
trustworthy prediction — see `extras/tests/test_jwt_security.py`,
`qknee/tests/test_provenance.py`, and `qknee/tests/test_model_health.py`
for the regression tests.

## Benchmark numbers: one source, reproduced in more than one place

The only real, ground-truth benchmark this project has is
`qknee/artifacts/kaggle_benchmark_summary.json` (real RSNA Knee data, n=58
studies), generated by `qknee/models/evaluate.py` and narrated in
`RESULTS.md`. More than one place currently *states* these numbers:

1. `RESULTS.md` (the canonical narrative, with full methodology/caveats).
2. `README.md`'s "Key metrics" section (states it reproduces `RESULTS.md`
   verbatim).
3. `frontend/components/landing/BenchmarksTable.tsx` — a **static
   reproduction** of the same three numbers (0.6574 / 0.5596 / 0.5579
   macro-AUC), with a code comment naming its exact source file and an
   on-page disclaimer that the hybrid VQC trails both classical baselines.

**Known residual risk, not a current contradiction**: `BenchmarksTable.tsx`
is a compile-time constant, not a live fetch from
`kaggle_benchmark_summary.json` — if that file is regenerated with new
numbers, someone has to update these places by hand. A build-time or
request-time fetch from the same JSON file would close this gap.

## Parameter-efficiency benchmark (VQC vs. classical baselines)

`scripts/run_vqc_vs_mlp_kfold.py` (see `RESULTS.md` Sec. 4/4a/4b) is the
project's answer to "does the quantum circuit do anything, or is it a
gimmick" — three real, run baselines, not assertions:

1. **Parameter-matched** classical MLP (41 params, same as the VQC): no
   measurable difference across 5 seeds — a genuine "not worse than an
   equally-tiny classical model" result.
2. **Realistically-sized (unmatched)** classical MLP (65,793 params, on
   the raw ResNet embedding, no PCA/quantum bottleneck): macro-AUC stays
   flat across this ~1,600x parameter range on the 58-study dataset — the
   headline parameter-*efficiency* claim, never framed as a quantum
   accuracy win.
3. **Sample-efficiency sweep** (25%/50%/100% of training data): reported
   as preliminary/single-seed and explicitly flagged as noisy at this
   sample size, not oversold.

`qknee/tests/test_vqc_layers.py`'s `TestParameterShiftGradients` class
additionally verifies the circuit is trainable under the parameter-shift
rule (the hardware-realizable gradient method), not just under the
simulator-only `backprop` the production config defaults to — evidence
this ansatz wasn't only ever exercised in a way that couldn't survive
contact with real hardware.

## Directory map

| Directory | What it is |
|---|---|
| `qknee/models/`, `qknee/data/`, `qknee/xai/`, `qknee/config/` | The ML pipeline itself (ResNet18 -> PCA -> VQC -> Grad-CAM) |
| `qknee/observability/` | Shared provenance/model-health vocabulary, consumed by the API and surfaced to the frontend |
| `extras/api/` | The FastAPI backend — the judged backend |
| `extras/deployment/` | Docker/Render/Vercel config for the FastAPI backend |
| `frontend/` | The Next.js clinical workstation — the judged frontend |

---

## Exactly which command starts what

| Component | Command | Notes |
|---|---|---|
| **FastAPI backend** | `uvicorn extras.api.server:app --reload --port 8000` | Needs `pip install -r requirements.txt -r extras/api/requirements.txt` and a JWT secret (`extras/api/.env.example`) — see `extras/README.md` §"Security configuration". |
| **Next.js frontend** | `cd frontend && npm install && npm run dev` | Reads `NEXT_PUBLIC_API_URL` (defaults to the FastAPI backend's deployed Render URL); see `frontend/.env.local.example`. |

`README.md` §"Run locally" documents these same two commands for a new
developer, in this order.
