# Q-Knee dependencies, audited for Streamlit Community Cloud / Hugging
# Face Spaces (free-tier: <1GB RAM during container spin-up, and a build
# times out if pip has to resolve/download multi-GB wheels). The two
# levers that actually matter at that scale are below; everything else in
# this file is comparatively small (single-digit-to-low-double-digit MB).
#
#   1. CPU-only torch/torchvision wheels (`--extra-index-url` + the `+cpu`
#      local version below) instead of PyPI's default CUDA build. This is
#      the dominant win: PyPI's default `torch` wheel bundles the NVIDIA
#      CUDA/cuDNN runtime and is 800MB-2GB+ depending on version, which
#      alone can blow both the RAM budget and the build-time limit on a
#      free-tier container that has no GPU to use it with anyway. The
#      `+cpu` local-version pin forces pip to resolve against the PyTorch
#      CPU index (~150-200MB total for both packages) instead.
#   2. `opencv-python-headless`, not `opencv-python` — ships without the
#      Qt/GTK GUI toolchain a headless server container never uses, which
#      is both a much smaller wheel and avoids missing-shared-library
#      install failures on a minimal Debian slim base image.
#
# PennyLane note: this project only ever simulates a 4-qubit circuit
# (`config.yaml`'s `quantum.n_qubits`), whose full state vector is 16
# complex amplitudes — trivial for PennyLane's default `default.qubit`
# (pure-Python/NumPy) simulator. The compiled `pennylane-lightning`
# backend exists for much larger qubit counts; pulling it in here would
# add a native-extension wheel for no simulation-speed benefit at n=4, so
# it's deliberately not listed.
--extra-index-url https://download.pytorch.org/whl/cpu

# qknee/api/auth.py — JWT signing/verification + password hashing.
# Deliberately PyJWT + argon2-cffi (Argon2id), NOT python-jose[cryptography]
# / passlib[bcrypt]:
#   - passlib[bcrypt]: passlib 1.7.4's bcrypt backend reads a
#     `bcrypt.__about__` attribute that bcrypt>=4.1 removed, breaking every
#     hash()/verify() call outright (`AttributeError`) — verified against
#     this project's actual pinned `bcrypt` transitive version, not a
#     hypothetical. Argon2id is also the current OWASP-recommended default
#     for new applications, not just a workaround.
#   - python-jose[cryptography]: no compatibility issue, just redundant —
#     PyJWT already covers this project's one JWT use case (HS256
#     sign/verify), and this file's whole premise is minimizing free-tier
#     footprint, so a second full JWT library sitting unused isn't added
#     for its own sake.
argon2-cffi==25.1.0
PyJWT==2.13.0

# Optional PostgreSQL/Redis storage backends (qknee/api/auth.py's
# SQLAlchemyUserRepository, qknee/api/server.py's CacheService) — both
# packages below are small/pure-Python-ish and safe to install
# unconditionally, but neither actually *requires* a Postgres/Redis
# server: with $DATABASE_URL/$REDIS_URL unset (the default on a
# single-node free-tier deployment), SQLAlchemy is only ever used against
# the stdlib `sqlite3` driver and redis-py's client is never connected —
# both modules degrade to a local JSON store / in-process cache instead.
#   - A Postgres DBAPI driver (`psycopg2-binary` or `psycopg[binary]`) is
#     deliberately NOT pinned here: it's only imported (lazily, inside
#     SQLAlchemyUserRepository) if `$DATABASE_URL` actually names a
#     `postgresql://` URL. Install one yourself alongside this file if
#     you're pointing at a real Postgres instance; if it's missing,
#     SQLAlchemyUserRepository's construction fails loudly and
#     `_build_user_repository()` catches that and falls back to
#     LocalFileUserRepository rather than crashing the API.
SQLAlchemy==2.0.52
redis==6.4.0
